# 1.x → 2.x

升级前备份数据库、上传文件、配置和自定义主题，并保留旧版程序与依赖锁文件。先在站点副本中演练，禁止直接在唯一一份生产数据上试升级。

1. 准备新版要求的 Node.js 环境。
2. 选择继续使用旧源码布局，或创建新版独立项目后迁移站点配置、数据库连接、上传文件及主题。不要对旧数据库重新执行新站点初始化。
3. 自定义主题从 Nunjucks 迁移到 Eta；先使用新版默认主题验证内容，再迁移样式和扩展。
4. 启动新版并检查数据库迁移日志。新版后台使用 JWT Cookie，首次升级后需要重新登录。
5. 检查文章、页面、分类、图片、评论、固定链接、后台登录和权限，再切换正式流量。

如验证失败，停止新版，恢复旧程序和升级前数据库备份。不要让旧程序继续写入已经迁移的数据库。

跨版本差异请以目标版本发布说明为准，不能用简单覆盖模板代替迁移。
